# Phase 2 / 2.10：记牌器滚动，取消按行数压缩

先读 `docs/tasks/_common.md`、`AGENTS.md`「线程与时序」，再读 `docs/archive/tasks/` 里 Phase 1 / T8 动效和 Perf P2 两本（行高、位图缓存、动效与压缩的关系）。

## 要什么（用户，2026-10-07）

打出的牌多了以后，记牌器按行数把行高压小（上游行为，V1 起宽度跟着缩），整块浮窗变得很小，而且再多就看不全。
用户要：**列表能滚动，行不再缩小**，不管打出多少牌都能看到。我方和对方记牌器都要。

## 定下来的做法（总指挥定，用户授权）

- 行高固定为未压缩的基准行高，宽度不再跟着缩。
- **只有已打出段滚动**：牌库段、手牌段始终完整显示；已打出段占面板剩下的高度，内容超出时在段内滚动，段头不随内容滚走。
- 牌库 + 手牌本身就放不下（面板高度设得很小）时，退回现在的压缩行为，报告里说明触发条件。
- 平铺模式（`group_cards_by_zone` 关）没有已打出段：整个列表滚动。

## 硬约束

- **鼠标点击照旧穿透到炉石**。overlay 锁定时不接收鼠标事件（`OverWindowController`），滚轮怎么拿到由你查清现状后定；不得为此让记牌器挡住炉石的点击 / 拖牌，不得新增需要辅助功能权限的监听。只有光标在该记牌器上时才滚它。
- 有新牌进已打出段时，用户能看到它（停在哪、要不要自动滚到新行由你定，报告写理由）；一局结束 / 新对局开始滚动位置复位。
- 滚动时卡条悬停浮窗（卡图、相关牌）指向光标下真实的那一行。
- 能滚动时要看得出来（还有内容在下面 / 上面），不抢眼。
- T8 动效在不滚动时行为不变；滚动中不许掉帧、不许出现行错位。位图缓存（Perf P2）照用。
- 红龙面板靠记牌器 view model 的 `left / top / height / scaling` 让位：记牌器占的矩形语义不能变，或者同步改 `RDOverlayGeometry.trackerBox` 并说明。
- 写 view model 遵守 `AGENTS.md` 线程规则；改时序前在报告里列出写入到显示的每一跳。

## 可改的文件

`HSTracker/UIs/Trackers/SwiftUI/` 下的文件、`HSTracker/UIs/Trackers/` 下承载记牌器面板的文件、`HSTrackerTests/` 下记牌器相关测试。
其它上游文件非改不可时最小改，报告写行数和理由。

## 验收

- 受限环境 `build` 过；改动中只跑记牌器相关测试类，交付前全套一次（`-skip-testing:HSTrackerTests/LocalizationFormatTests`），报告条数。
- 新测试：行数超出时行高不变且可滚；牌库 + 手牌放不下时的回退；滚动位置复位。
- 报告：滚轮事件怎么拿到、为什么不挡点击；滚动区域的边界怎么算；自动滚动策略；动了哪些上游文件。
- 🎮（由人做）：打一局牌多的对局——已打出段超出后行不缩小、滚轮能滚、炉石里拖牌点击不受影响；对方记牌器同样。
